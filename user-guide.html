Before you begin

RepoXray is intended for public GitHub repositories. Use the repository's main URL in the form https://github.com/owner/repository. Private repositories and metrics temporarily unavailable through GitHub may not be analyzable in the current version.

SECTION 02

Understanding Your Results

Learn what each metric represents, what it can reveal, and what it cannot tell you on its own.

METRICWHAT IT TELLS YOU
Code FrequencyTracks lines of code added and removed over time. Large spikes can point to a new feature, refactoring, dependency updates, or cleanup. Lines changed alone are not a measure of code quality.
Repository ActivityShows how commit activity changes across the selected period. Regular activity may suggest ongoing development, while quieter periods are not automatically a problem; projects work at different rhythms.
ContributorsLists people credited for contributions and helps you see how work is distributed. Results can vary with merge patterns, author identity, API limits, and the repository history available.
CommitsShows recorded changes in the repository history and the count available for the chosen time window. Commits differ in size and importance, so a higher count does not necessarily mean better progress.

HOW TO READ THE METRICS

Look at the metrics together and consider the project's age, size, release schedule, and development style. Treat them as signals to explore—not as a score of project quality. If a chart or count is unavailable, check the selected repository and try again later.

SECTION 03

Common Problems

Use these checks when a repository does not load, a request fails, or a metric is missing.

Invalid repository URL

Use a URL in the form https://github.com/owner/repository. Include both the owner and repository name. Remove extra paths such as /issues, /pulls, /blob/main, or /tree/main, then submit the main repository URL again.

Repository not found

Open the URL directly on GitHub and confirm the repository still exists. Check the spelling of the owner and repository name and make sure the repository is public. A private, deleted, or renamed repository may return a not-found response.

Analysis failed

Check your connection and retry after a short pause. GitHub may limit repeated unauthenticated requests, the repository may be unusually large, or a service request may have failed temporarily. If the issue continues, try a smaller public repository to identify whether the problem is specific to one project.

Some metrics are missing

A repository can load successfully even if a particular metric is unavailable. Some GitHub statistics are calculated asynchronously or have limits on the date range and data returned. Wait briefly, reload the analysis, and read any status message shown beside the metric instead of assuming a missing value means zero.

Still stuck?

Copy the repository URL, note the exact message displayed, and try the same flow with another public repository. Comparing the results can help distinguish a URL problem from a temporary API or repository-specific issue.
