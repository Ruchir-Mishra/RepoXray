SECTION 01

Getting Started

Start with a public repository, submit its canonical GitHub URL, and use the available insights to understand how the project changes over time.

01 ▢

Copy Repository URL

Open the repository on GitHub and copy its main page URL from the browser address bar. Use the repository home page rather than an issue, pull request, file, or branch page.

Standard URL format
02 ↪

Enter the URL

Return to the RepoXray Home page, paste the full URL into the input field, and select Analyze Repository. Check that the owner and repository name are both present before submitting.

URL format validation
03 ↗

Review Results

When analysis completes, review the summary and available activity, contributor, commit, and code-frequency information. The metrics shown depend on the data returned by GitHub.

Before you begin

RepoXray is intended for public GitHub repositories. Use the repository's main URL in the form https://github.com/owner/repository . Private repositories and metrics that GitHub cannot currently provide may not be available for analysis.

SECTION 02

Understanding Your Results

Learn what each repository metric represents, what information it provides, and how it can help you understand a project's development.

METRIC WHAT IT TELLS YOU
⌁ Code Frequency Shows how much code is added or removed over time. It can help highlight larger changes, refactoring, or maintenance activity.
ϟ Repository Activity Shows how commit activity changes over the selected period. This helps you understand development patterns and maintenance activity.
♧ Contributors Shows who has contributed to the repository and, when available, how contributions are distributed across project collaborators.
◷ Commits Shows commit history and, where available, the number of commits reported for the repository or selected time window.
i

Interpreting the metrics

Metrics provide different perspectives on repository activity. A high commit count alone does not establish code quality, and a quiet period does not necessarily indicate that development has stopped.

SECTION 03

Common Problems

Find explanations and practical steps for resolving common problems when submitting or analysing a repository.

↗ Invalid repository URL ⌄

Make sure the URL points to the repository's main GitHub page. A standard repository URL looks like:

https://github.com/owner/repository

Check that the owner and repository name are present. Do not submit a URL pointing to an issue, pull request, file, or branch.

⌕ Repository not found ⌄

Open the repository directly on GitHub and check that it exists and is publicly accessible. Confirm that the repository owner's name and repository name are spelled correctly.

Private, renamed, or deleted repositories may not be available to the current version of RepoXray.

ϟ Analysis failed ⌄

Check your internet connection and try again. Some GitHub statistics may be temporarily unavailable, and API rate limits can affect requests.

If the problem continues, check the error message shown by RepoXray. Different failures may require different solutions.

?

Still having trouble?

Recheck the repository URL and try submitting it again. If your team has configured a project issue tracker, report persistent errors there with the repository URL and the displayed error message.
